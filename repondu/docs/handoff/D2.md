# Handoff D2 — Détection des nouveaux avis

## Fait
- Source de vérité = la fiche Maps du prospect lié (`app/service/loop.py::refresh_reviews`,
  réutilise `scraping.reviews.scrape_prospect`) ; un avis est « nouveau » si son `review_id`
  était inconnu. Filet de sécurité : tous les clients actifs (`manager_added`) sont
  rafraîchis toutes les `SERVICE_REVIEW_CHECK_HOURS` (6) heures par le scheduler
  (`run_service_cycle`), `POST /service/run`, `repondu service-run [--force]`.
- Notifications Google (`app/service/notifications.py`, boîte `MANAGER_IMAP_*`) : filtre
  expéditeur `@google.com`, extraction du nom d'établissement / auteur / note / extrait (FR et
  EN, texte ou HTML), appariement par nom normalisé (`match_establishment`), puis
  rafraîchissement immédiat et rédaction (`poll_manager_inbox`). Événement journalisé même
  sans correspondance.
- Tests : parseur (FR/EN), appariement, rafraîchissement avec faux scraper, boîte gestionnaire
  avec faux fetcher.

## Limites
- Le format des notifications Google change ; l'appariement par nom suffit car la notification
  ne sert que de déclencheur. Sans IMAP configuré, le filet de sécurité 6 h fonctionne seul :
  délai maximal avis → brouillon ≈ 6 h, compatible avec le DoD < 24 h de D3.
