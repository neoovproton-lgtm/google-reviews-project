# Handoff C2 — Séquence d'envoi

## Fait
- Tables `mailboxes`, `outreach` (une séquence par prospect, contrainte unique), `outreach_messages`
  (unique par (séquence, étape)), `email_events`, `optouts`.
- `app/outreach/mailboxes.py` : `data/mailboxes.json` (voir `data/mailboxes.example.json`,
  identifiants IMAP jamais copiés en base), `repondu mailboxes --sync`, quota effectif avec
  montée en charge 20 → 23 → 27 → 30 /jour selon `warmup_started_at`, rotation (boîte la moins
  sollicitée du jour, boîte du fil conservée si elle a du quota), santé (C5).
- `app/outreach/email_providers.py` : Resend et Brevo (httpx), `LogProvider` sans clé,
  `set_provider()` pour les tests, parseurs de webhooks (C5). En-tête `List-Unsubscribe`.
- `app/outreach/sequence.py` : enrôlement des `enriched` avec canal et contact, hors registre
  d'opt-out ; fenêtre d'envoi jours ouvrés `OUTREACH_SEND_HOURS` heure de Paris ; J0 → J+3
  (relance avec 1 nouvel avis) → J+8 (dernier) → `done` ; un message composé une fois par
  étape, jamais renvoyé s'il est `sent` (reprise après coupure testée) ; échec d'envoi →
  `failed` puis nouvel essai au prochain passage sans recomposer ; `record_outcome`
  (`replied|yes|objection|opted_out|no|stopped`), `opt_out` (registre + clôture), `mark_bounced`.
- API : `POST /outreach/run` (job en arrière-plan), `GET /outreach?status=&channel=`,
  `GET /outreach/{id}` (avec messages), `POST /outreach/{id}/outcome`, `GET /mailboxes`,
  `POST /mailboxes/sync`, `POST /mailboxes/{id}/resume`. CLI `repondu outreach-run`,
  `repondu mailboxes`.
- Tests : 10 (fenêtre, montée en charge, enrôlement, séquence complète en voyageant dans le
  temps, reprise, panne, quotas et rotation, arrêt sur réponse / opt-out, API).

## Points d'attention
- Planifier `repondu outreach-run` toutes les heures (cron / OpenClaw) : la fenêtre d'envoi et
  les quotas font le reste. Un seul job à la fois (verrou API).
- Les dates `next_action_at` sont en UTC ; la fenêtre est évaluée en heure de Paris.
- Les autres canaux (`formulaire`, `instagram`, `facebook`, `sms`) sont enrôlés mais leurs
  handlers arrivent en C3 (`CHANNEL_HANDLERS`).
