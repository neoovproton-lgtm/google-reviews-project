# Handoff A4 — Enrichissement contact et canal prioritaire

## Fait
- `app/enrichment/extract.py` (pur, testé, selectolax) : emails (`mailto:`, texte, forme
  obfusquée `x [at] y [dot] fr`), filtrage des adresses techniques (sentry, hébergeurs,
  `noreply`, faux positifs d'images `logo@2x.png`), classement : adresse générique
  (`contact@`, `info@`, `reservation@`…) sur le domaine du site en premier ; formulaire de
  contact (formulaire avec champ email/textarea, formulaires de recherche ignorés) ; handles
  Instagram (`/p/`, `/reel/`… ignorés) et Facebook (`sharer`, `plugins`… ignorés ; formes
  `pages/…/id` et `profile.php?id=` gérées) ; téléphones FR normalisés, mobile = 06/07.
- `app/enrichment/website.py` : httpx via `PROXY_URL`, page d'accueil puis jusqu'à 3 pages
  candidates (liens « contact »/« mentions » du site, puis sondage de `/contact`,
  `/nous-contacter`, `/mentions-legales`). Un site qui est une page Facebook/Instagram donne
  directement le handle ; les plateformes (Uber Eats, TheFork, Linktree…) sont ignorées.
- `app/enrichment/channel.py` : `canal_prioritaire` = `email > formulaire > instagram >
  facebook > sms (mobile) > telephone (fixe)`. Un seul canal par prospect (PRD C3).
- `app/enrichment/run.py` : traite les `qualified` par score décroissant, statut `enriched`
  même en cas d'erreur (canal déduit du téléphone Maps), erreur conservée dans
  `enrich_error`, `--retry-errors` pour rejouer.
- `GET /stats` → `qualified.written_channel_rate` = part des qualifiés avec un canal écrit
  (cible PRD ≥ 80 %). CLI `repondu enrich [--limit N] [--retry-errors]`,
  API `POST /scrape {"mode":"enrich"}` ; `mode: "all"` enchaîne A1 → A4.
- Tests : 93 verts, dont un bout en bout contre un mini-site servi en local.

## Limites connues
- Sans site web dans Maps, le seul canal possible est le téléphone (SMS si mobile). Le DoD
  « ≥ 80 % avec un canal écrit » se mesure sur le VPS avec `GET /stats` ; si l'on est
  en dessous, piste : recherche du site par le nom + ville (moteur de recherche) — hors A4.
- Pas de rendu JavaScript côté site (httpx seulement) : les sites 100 % JS (Wix, certains
  Squarespace) peuvent ne rien donner. Bascule possible vers Playwright pour ces cas.
- Les numéros mobiles trouvés sur les sites sont parfois ceux d'un prestataire ; à valider
  humainement avant tout SMS (cadre légal PRD §5).

## Pour la Phase B
- La table `reviews` contient texte, note, réponse existante : c'est l'entrée de B1.
- `prospects.negative_unanswered_last_30d` et `unanswered_last_30d` alimentent le mail C1.
