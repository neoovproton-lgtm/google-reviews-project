# Handoff C5 — Délivrabilité

## Fait
- Webhooks : `POST /webhooks/resend` (signature Svix vérifiée si `RESEND_WEBHOOK_SECRET`),
  `POST /webhooks/brevo?token=…` (jeton `BREVO_WEBHOOK_TOKEN`, accepte un objet ou une liste).
  Parseurs dans `email_providers.py`, application dans `app/outreach/events.py`.
- Effets : `delivered` / `opened` (statut et horodatage du message, compteurs de la boîte,
  doublons ignorés), `bounced` (message `bounced`, séquence `bounced`), `complained`
  (opt-out du contact + coupure immédiate de la boîte). Chaque événement est journalisé dans
  `email_events`.
- Coupure automatique (`mailboxes.check_health`) : plainte spam → coupure ; sinon, après
  `OUTREACH_MIN_SENT_FOR_RATE` (20) envois, `bounced_total / sent_total >
  OUTREACH_MAX_BOUNCE_RATE` (0,03) → `active = 0`, `paused_reason`. Réactivation :
  `repondu mailboxes --resume <adresse>` ou `POST /mailboxes/{id}/resume`.
- `GET /stats.mailboxes` et `GET /mailboxes` : par boîte, quota du jour, envoyés (jour, total),
  délivrés, ouverts, bounces, plaintes, taux de bounce, semaine de warm-up, statut.
- Warm-up : outil externe ; `warmup_started_at` (dans `mailboxes.json`) pilote la montée 20 → 30.
- Tests : 7 (parseurs, cycle délivré → ouvert → bounce → plainte, seuil et minimum, signature
  Svix, endpoints, signature exigée).

## À configurer sur le VPS
- Resend : webhook `https://<domaine>/webhooks/resend`, événements delivered / bounced /
  complained / opened, secret dans `RESEND_WEBHOOK_SECRET`.
- Brevo : webhook transactionnel `https://<domaine>/webhooks/brevo?token=<BREVO_WEBHOOK_TOKEN>`.
- Les ouvertures dépendent du pixel de suivi du fournisseur ; le PRD demande d'éviter les liens
  trackés les premiers jours : désactiver le suivi des clics côté fournisseur, garder les
  ouvertures si souhaité.
