# Handoff A3 — Scoring, filtre, liste qualifiée exportable

## Fait
- `app/scoring.py` (pur, testé) : `compute_score = avis_par_mois × (1 − taux_reponse)` ;
  `is_qualified` : `≥ SCORE_MIN_REVIEWS_PER_MONTH` (10) **et** `< SCORE_MAX_RESPONSE_RATE`
  (0,5 ; 50 % exact = non qualifié). `score_all()` rescore tous les prospects ayant des
  métriques, statut `qualified`/`disqualified` ; les `enriched` gardent leur statut mais leur
  score est rafraîchi. Idempotent.
- `app/export.py` : sélection triée par score décroissant, CSV (colonnes de prospection :
  identité, métriques, score, contacts A4, `canal_prioritaire`, `maps_url`).
  « qualified » à l'export inclut les `enriched`.
- CLI : `repondu score`, `repondu export --status qualified --limit 300` → `data/exports/`.
- API : `GET /prospects/export.csv?status=qualified&limit=300&city=`,
  `GET /prospects?status=qualified` déjà trié par score, `GET /stats` (comptes par statut, par
  ville, jobs, couverture contact). `POST /scrape {"mode":"score"}`.
- Tests : 76 verts (bords 10 avis/mois exact et 50 % exact, statuts, export, endpoint).

## Point d'attention
- Le DoD « 150–300 prospects qualifiés » dépend des passes A1/A2 sur le VPS. Si la liste est
  trop courte, deux leviers sans code : `REVIEWS_MIN_TOTAL` (élargir A2) et
  `SCORE_MIN_REVIEWS_PER_MONTH` (abaisser à 8). Si trop longue, `--limit 300` à l'export
  garde les meilleurs scores.

## Pour A4
- Travailler uniquement sur `status = qualified` ; `website` est rempli en A1/A2 quand Maps
  l'affiche. Sans site, il reste le téléphone (mobile → SMS) et la recherche du handle
  Instagram/Facebook n'est possible que depuis le site.
