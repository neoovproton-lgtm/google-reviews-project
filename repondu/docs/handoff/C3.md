# Handoff C3 — Multicanal

## Fait
- Un seul canal par prospect : `outreach.prospect_id` unique ; le canal est `canal_prioritaire`
  à l'enrôlement. Handlers dans `app/outreach/channels.py`, enregistrés dans
  `sequence.CHANNEL_HANDLERS`.
- **Formulaire** (`app/outreach/forms.py`, Playwright) : choix du formulaire contenant un
  `textarea` (les formulaires newsletter sont ignorés), reconnaissance des champs par
  nom/id/placeholder/label (nom, email, téléphone, objet, société), cases de consentement
  obligatoires cochées, soumission, confirmation détectée (« merci », « envoyé »… ou changement
  d'URL). Message sans LLM (`compose_form_message`) avec les 2 réponses et l'adresse de retour
  `OUTREACH_REPLY_ADDRESS`. Échec → séquence `stopped` avec la raison.
- **DM Instagram/Facebook** : texte rédigé (≤ 80 mots) + 2 réponses, statut `manual_pending` ;
  livraison par lot (`OUTREACH_DM_BATCH` = 30) via Telegram `/dm`, `repondu dm-batch` ou
  `POST /outreach/dm-batch` ; `/envoye <id>` ou `POST /outreach/messages/{id}/sent` marque
  `manual_sent`.
- **SMS** : modèle court en code avec lien public `GET /p/{token}` (page minimale, `noindex`,
  affiche les 2 réponses), fournisseur Brevo SMS (`BREVO_API_KEY`) ou `LogSms`, « STOP »
  dans le texte, fenêtre jours ouvrés/heures commune à tous les canaux.
- Ces trois canaux n'ont pas de relance automatique : après envoi, `next_action_at = None` ;
  sans réponse après 10 jours (`expire_stale`), la séquence passe en `done`.
- Tests : 7 (formulaire de fixture rempli et soumis, bout en bout, échec, DM lot + marquage,
  SMS + page publique, unicité du canal, API).

## Points d'attention
- Le formulaire est soumis avec `OUTREACH_REPLY_ADDRESS` : cette adresse doit exister et être
  relevée (IMAP, C4) pour capter les « OK ».
- Réponses SMS entrantes (« OK », « STOP ») : pas de webhook Brevo entrant branché ; à saisir
  via `POST /outreach/{id}/outcome` en attendant (voir C4).
- `PUBLIC_BASE_URL` doit être l'URL HTTPS publique de l'API pour que le lien SMS fonctionne.
