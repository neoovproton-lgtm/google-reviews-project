# Handoff B1 — Prompt de rédaction des réponses

## Fait
- `app/llm.py` : `AnthropicLLM` (SDK `anthropic` 1.x, `client.messages.parse` avec sortie
  structurée, modèle `ANTHROPIC_MODEL` = `claude-sonnet-5`, thinking adaptatif, effort moyen,
  prompt système en cache via `cache_control`). Erreurs API converties en `LLMError` ; refus
  et troncature détectés. `set_llm()` permet d'injecter un faux (tests : `tests/fakes.py`).
- `app/replies/prompt.py` : `SYSTEM_PROMPT` (règles PRD : ton par note, vouvoiement, reprise
  d'un élément concret, pas d'excuse générique, pas de promesse commerciale, pas de signature,
  pas d'IA/emoji), `build_user_message` (profil, avis, consigne, retour de relecture),
  `REVIEWER_SYSTEM` pour la relecture des ≤ 2★. Sortie `ReplyOutput{reply, detail_reused}`.
- `app/replies/checks.py` : vérifications en code (60/90 mots, excuses génériques, promesses,
  tutoiement, IA, emoji, éléments interdits du profil, signature incluse, élément concret
  repris, invitation hors ligne pour ≤ 2★). La signature est ajoutée par le code.
- `app/replies/generator.py` : 2 tentatives max, retour des problèmes au modèle, relecture par
  un second appel pour ≤ 2★ (PRD §5), meilleure tentative conservée et `needs_human` si
  non conforme.
- `repondu eval-replies` : 30 avis test (`data/eval/reviews_test.json`, 8×5★, 6×4★, 6×3★,
  5×2★, 5×1★, dont avis vides/« Top ») → `data/exports/eval-replies-<date>.md` avec cases à
  cocher. Le DoD (≥ 27/30 sans retouche) est une validation humaine à faire avec une clé API.
- Tests : 123 verts (prompt, chaque vérification, générateur avec FakeLLM, évaluation).

## Non fait
- Aucun appel réel à l'API depuis cet environnement (pas de clé). À faire sur le VPS :
  `ANTHROPIC_API_KEY=… repondu eval-replies`, relire, ajuster le prompt si < 27/30.
- Coût estimé par réponse : ~1 500 tokens en entrée (dont ~900 en cache) + ~150 en sortie,
  soit < 0,01 € ; ~400 réponses/mois ≈ 2–3 €.
