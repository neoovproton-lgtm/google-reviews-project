# Handoff B3 — Profil établissement, onboarding Telegram, veto/validation

## Fait
- Schéma : `establishments` (nom, cuisine, ton, signature, prénom du gérant, à ne jamais dire,
  tutoiement, délai de veto `auto_publish_delay_h` = 24, `telegram_chat_id`, `contact_email`,
  lien `prospect_id`), `replies` (brouillons : texte, `needs_human`, `safety_flags`,
  `check_issues`, statut `pending|approved|rejected|published`, décision), `telegram_sessions`
  (état du formulaire). Créés/migrés par `init_db()`.
- Telegram (`app/telegram/`) : client Bot API (`HttpTelegram`, `NullTelegram` sans jeton,
  `set_telegram()` pour les tests), bot avec `/start`, `/onboard` (5 questions → profil),
  `/profils`, `/annuler`, boutons « Approuver / Refuser » sur chaque brouillon. Allowlist
  `TELEGRAM_CHAT_ID`, secret de webhook `TELEGRAM_WEBHOOK_SECRET`.
- Service (`app/replies/service.py`) : brouillons pour les avis sans réponse du prospect lié,
  notification Telegram avec « publication automatique dans 24 h sauf veto » (ou « pas de
  publication sans votre accord » si `needs_human`), décision, approbation automatique à
  l'expiration du délai (jamais pour `needs_human`).
- API : `POST/GET /establishments`, `POST /establishments/{id}/draft`, `GET /reviews/pending`,
  `POST /reviews/{review_id}/decision {approve|reject, text?, by?}`,
  `POST /reviews/auto-approve`, `GET /replies?status=`, `POST /telegram/webhook`.
- CLI : `repondu draft -e <id>`, `repondu auto-approve` (à planifier toutes les heures),
  `repondu telegram-webhook --url https://…/telegram/webhook`.
- Tests : 158 verts (formulaire bout en bout, annulation, allowlist, boutons, flux API complet
  avec FakeLLM + FakeTelegram, veto 24 h, secret de webhook).

## Non fait / prochaines étapes
- La **publication** sur Google (statut `published`) reste semi-manuelle (PRD) : un humain colle
  la réponse approuvée depuis le compte gestionnaire. `GET /replies?status=approved` est la
  file à traiter ; D3 ajoutera le marquage `published` et le log.
- L'onboarding ne demande pas l'email de contact ni le lien prospect : à faire via
  `POST /establishments` ou une 6ᵉ question si besoin (PRD : 5 questions).
- Mettre en place le webhook sur le VPS : HTTPS obligatoire (reverse proxy devant :8000), puis
  `repondu telegram-webhook --url https://<domaine>/telegram/webhook`.
- Planifier `repondu auto-approve` (cron horaire ou routine OpenClaw).
